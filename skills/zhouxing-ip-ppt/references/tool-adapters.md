# 工具能力与 agent 适配

默认交付飞书原生幻灯片。先识别当前 agent 已有能力，复用能写独立文字、形状、图片并提供页面预览的飞书工具；例如豆包已有的 PPT Skill、飞书连接器或已授权的 lark-cli。工具名字不同不影响使用，不因缺少同名 Codex Skill 就安装另一套引擎。核心画风、字体、间距和图文关系仍遵循本 Skill。

## 安装的最短路径

1. 完整安装 `zhouxing-ip-ppt` 目录，保留 SKILL.md、references、scripts、assets 和许可。只核对入口及默认主题、母图、样机文件可读，不默认遍历所有文档、逐文件哈希、注册所有字体或运行正反例测试。
2. 识别现有飞书工具：能创建原生页、回读和预览就沿用；安装阶段无需调用接口创建试稿，也不必为了列出能力而发起账号授权。
3. 可直接使用时简短交付：“已安装，默认生成可编辑的飞书幻灯片，配色随角色与内容确定。发我主题或原稿即可。”若尚缺工具/授权，说明具体状态，并按下节给一个当前操作入口。授权齐备之前不要说“已可制作”。

用户同时给了制作需求，装好后继续做已授权的稿件；只要求安装时不额外生成三张测试页。不默认输出依赖矩阵、全部日志、长篇能力报告或未用到的本地 PPTX 缺项。用户要求排障/完整验收时才展开相应细节，实际错误始终如实报告。

`agents/openai.yaml` 是 Codex 界面元数据，其他 agent 可忽略；无需复制 Codex 私有运行时、配置或账号。本 Skill 不内置用户文章、截图、凭据或演示稿。

## 缺少飞书时的引导

按实际缺口只走一条路径，已经满足的步骤不重复做。

| 当前情况 | 下一步 | 无需做的事 |
|---|---|---|
| 已有可用且授权的飞书 PPT 工具 | 直接按原生协议制作、回读、截图 | 重装飞书、检查本地 PPTX 引擎 |
| 已有工具但未登录/授权或权限不足 | 用工具原有连接/登录入口；只申请本次幻灯片与必要媒体权限 | 重装 Skill、索取用户密码或复制别人凭据 |
| 无飞书工具，有终端执行和安装能力 | 按当前官方说明安装 lark-cli；读取其幻灯片与授权协议，再引导配置和登录 | 安装 LibreOffice、从源码构建 CLI |
| 无终端或环境禁止安装，亦无飞书工具 | 引导用户在该 agent 的工具/连接器设置中添加飞书；若平台不支持，明确此环境暂不能自动制作飞书稿 | 假装安装成功，或让用户运行此环境无法执行的命令 |
| 用户没有飞书账号/客户端 | 提供飞书官网注册/登录入口；需要桌面查看时提供官方客户端下载页 | 将安装桌面客户端等同于 agent 已获得写入能力 |
| 用户明确要求本地 PPTX | 按交付协议启用本地引擎与预览路径 | 强制开通飞书 |

飞书官网：https://www.feishu.cn/ ；客户端下载：https://www.feishu.cn/download 。飞书网页端也可使用；是否安装桌面客户端不作为自动制作的先决条件。

### 官方 CLI 路径（仅缺少原生集成时）

来源为 [larksuite/cli 官方安装与 Agent 快速开始](https://github.com/larksuite/cli#quick-start-ai-agent)，命令执行前核对当前官方文档和本机 help。当前 npm 安装入口为：

```bash
npx @larksuite/cli@latest install
```

CLI 安装器负责其自身依赖与协议资源；优先使用已安装的 Node/npm，缺少时按当前环境权限规则准备，受限环境才给用户必要的一步指引。不要为了使用已发布二进制安装 Go 或编译源码。安装器的可选服务按本任务选择，不为 PPT 主动配置邮件、日历或消息权限。

仅首次缺应用配置时，按官方流程在后台运行 `lark-cli config init --new` 并及时展示其配置链接；已有有效配置不要新建应用。仅缺登录/权限时，先读当前 `lark-shared`/`lark-slides` 或本机 help，按实际支持的幻灯片及媒体范围发起授权；支持时使用 `--no-wait --json`，把原样链接和工具要求的二维码展示给用户，交还控制权让用户扫码。用户确认后按当前工具协议继续，不在链接尚未展示时阻塞轮询。

安装 Skill 不会替用户完成扫码、账号注册、租户管理员审批，也不应请求用户在聊天里发送密码、App Secret 或 access token。只需用户完成当前必要的一步；不要一次抛出后台配置、权限清单和完整开发手册。无法自动配置时说明真实缺口和官方入口。

## 制作时按需准备

- 角色/场景：使用当前 agent 支持实际参考图输入的生图能力，或用户已有匹配素材。缺少生图和素材时明确提示，不能假装生成。默认母图只用作画风参考，不能当作每页可复用的无关成品图。
- 原生排版与预览：默认飞书工具与服务端截图；无需本地 PPTX 引擎或本地渲染器。飞书服务端暂不能截图时如实说明，回读与几何检查不能冒充目标端预览。
- 对齐、间距、越界与真实字形/alpha 轮廓：使用已有等效工具；使用本 Skill 检查器时再准备 Python 3 和 Node/@napi-rs/canvas。检查标准不因换工具而降低，无法测量的项目不能报为已通过。
- 设备外框：资源已内置，无需联网找图或重画。需要本地套图时使用已有合成工具，或按需安装 canvas 后运行 compose_device_mockup.mjs。
- 字体：从当前工具和目标飞书实际可用的字体选择匹配组合；某个本地字体文件不兼容时换同类可用字体或采用目标端测量，不因一个 TTC 加载失败阻塞所有页面。

## 可选脚本依赖

`validate_plan.py` 和 `audit_layout.py` 只使用 Python 标准库。两个 `.mjs` 入口通过 `canvas_runtime.mjs` 解析 @napi-rs/canvas：先尝试 Skill 附近和当前工作项目的 node_modules，再尝试可选环境变量 RUNTIME_NODE_MODULES。依赖准备按当前环境规则完成，无需向用户展示例行命令。

```bash
node <skill-root>/scripts/measure_layout.mjs objects.json measured.json
python3 <skill-root>/scripts/audit_layout.py measured.json
node <skill-root>/scripts/compose_device_mockup.mjs --device iphone-14-pro-silver --input screenshot.png --output preview.png --layers-dir device-layers
```

没有 canvas 时，仅在实际要调用上述 Node 脚本、且没有等效工具时安装 `@napi-rs/canvas`。当前工作目录影响依赖查找；输入 JSON 的素材/字体相对路径以 asset_base 解析。字体不随 Skill 分发。显式请求 PPTX 才检查本地 PPTX 引擎和对应预览器，不把 python-pptx 或 LibreOffice 当作默认安装项。

安装与静态检查通过不等于制作效果已验证。首次实际制作时直接完成用户指定范围的原生稿，结合回读和目标截图验证；不额外要求用户批准三页能力测试，也不承诺不同 agent 的效果完全一致。
