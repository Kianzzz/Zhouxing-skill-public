# 视觉系统

数值为起点，参考图片不是源 PPT，不能声称辨认出准确字号与字体。先确定字体性格、信息几何和场景体量，再定数值。

## 默认配色

未指定项目配色时读取 `assets/default-theme.json`（相对 Skill 根目录）：品牌锚点草木绿 `#28A85B`，结构深绿 `#16733D`，辅助浅绿 `#C8F2D5`，近白绿面 `#F4FCF6`，纯白底 `#FFFFFF`。标题近黑 `#151A23`、正文 `#343B45`、次级说明 `#667085`。原生数字、标签、关键词和插画使用同一绿系，不因参考图是蓝色就漂回蓝色。

锚点绿用于角色衣服、局部道具和原生强调，浅绿用于有语义的色面或低对比背景数字；不为换主色而增加背板、改变字号间距或套用新构图。小号绿色文字用深绿；白底上的锚点绿优先用于图形或大字，锚点绿底的小胶囊用近黑文字，浅绿底用深绿文字，避免小号白字与绿色底的对比不足。

明确指定的项目配色可覆盖默认值，记录本项目色板并同步提示词和实际风格参考。更换默认母图只改变默认插画的强调色，不替用户 IP 的识别色、真人衣服、真实截图和设备金属框重新染色；品牌素材保留原色。

## 字体组合

“高级”不能用某个字体名保证，主要来自字形性格、标题密度、字重反差、行长、断行与插画的协调。禁止只把默认粗黑标题放大后称为字体设计。

| 视觉方向 | 标题 | 正文 | 英文/数字 | 适配 |
|---|---|---|---|---|
| 编辑叙事 | 思源宋体 Heavy/Bold 等有骨架的宋体 | 思源黑体 Regular/Medium | 克制衬线或同系无衬线 | 人物场景、主题观点，明确宋黑反差 |
| 图形商业 | 有紧凑字面的黑体 Heavy | 同系 Regular | 几何无衬线 | 原参考蓝白商业，靠大字与图形而非换装饰字体 |
| 轻盈人文 | 中等字重、清爽的无衬线 | 同系 Regular | 轻中等字重 | 原参考数字素养，避免所有字一律粗黑 |

每套通常两家族（标题与正文），英文/数字需要时至多一个补充；不是强制两家族，单家族可通过充分字重和尺寸反差成立。中文选择有完整字形的字体，字体缺失先找同类别替代并记录，不静默替成默认黑体。只宣称实际验证过的字体可用性。

960×540 中标题可从 38–64 设计单位起步，短封面可更大；正文 18–24，次级标签 13–16。以投影/资料用途、内容量和参考为准，不为了装下正文无限缩字。标题优先人工按语义断行，通常 1–2 行；同级标题统一节奏。页脚只保留必要的来源和页面定位，内容ID、调试路径、导出版本放备注或执行记录。标题/正文行距约 1.0–1.15 / 1.25–1.45。用深色正文，灰字只承担次级说明。

飞书的字号与坐标以其协议为准；Artifact Tool 的 geometry/fontSize 为 CSS px（96 DPI），fontSizePt 才是 pt。PPTX 使用 960×540 CSS px 时物理画布是 10×5.625 英寸，不能与 13⅓×7½ 英寸的坐标混用；导出后检查 EMU。不同路径转换按实际画布比例，不能简单认为 px=pt。

## 间距、对齐与可见轮廓

先建立页面 spacing_system。960×540 的默认主间距只用四档：tight=8（标题到正文）、related=16（同一信息组）、group=24（独立组）、outer=40（外边距与主要列沟）。这是起点，参考有明确节奏时可换一套；单页主间距档位不超过四个，同语义关系用同一个 token。4 单位仅可用于胶囊内部微调，不另造主体间距档位。不要把行距/字距与模块间距混为一类，也不要求所有空白都一样。

- 共享左对齐线、标题基线、段落起点和同级组的节奏。先把信息分组，再用“组内近、组间远”建立层级。
- 文本框按实际断行和字体测量，不用宽大的空文本框充当内容宽度；文本框的安全余量保留，但图文位置要按可见文字判断。
- 图片按 alpha 可见包围框与人物轮廓判断。透明文件边缘不能充当人物边缘；只测几何，不检查或重绘人物内容。
- 图文侧排时检查正文区域中贯穿多行的空白中缝。若存在明显空洞，先移动/放大/重排现有插画，或调整文字列宽及景别，不能放一条色块掩盖。图片轮廓允许有凹凸，短行的行尾空白不要求强行填满。
- 先用脚本或当前工具的等效能力测量字体渲染后的字形 alpha 和图片 alpha 范围；中文与英文混排不只依赖字体 API 的 bounding-box 数值，以免漏算后续字形。再按命名约束检查对齐、组间距和主要图文列沟；文字测量是估算，不等同飞书实际字形，最后必须看目标端截图。
- 明确有意留白的作用：阅读入口、信息分隔、视线通道、裁切余地；不得用“极简”解释所有空洞，也不以统一占满率塞装饰。

计划写入 spacing_system（最多四档主数值）和非空 layout_constraints（对齐、组内/组间、图文列沟及测量依据）。侧排图文页必须给主要正文组与图像的 gutter 写对象 ID、basis=ink 和光学范围；960×540 下可先以16–80检查常规侧排，具体范围由构图解释，不能看到超限后只放宽范围。主间距允许约±4的光学校正，需记录原因；不能每个对象另选一个随意数值。修改一组后联动同级组，而非单点移动。

## 原生文字表现手法

文字排版不仅是换字体。每套确定主机制，普通页每页通常一个主机制，可配一个轻量辅助；同功能同样式，不能把所有参考效果堆在一页。

| 机制 | 信息用途 | 原生实现与边界 |
|---|---|---|
| 低对比背景大数字 | 章节、步骤数、核心数量 | 原生数字在背景层，字号可从100–180起步，淡色；标记 decorative_reason，不承担必须读清的信息，不盖正文 |
| 胶囊标签 | 类别、状态、方法入口、案例标识 | 圆角形状和文字独立，内部留一致 padding；短标签，不能把整段正文塞成按钮 |
| 关键词/短句强调 | 核心动作或结论 | 同一强调色、字重或原生底色标记，控制数量；不是每行都加粗变色 |
| 分层说明 | 标题、组标题、正文、注释 | 固定角色样式和级差，例如44/25/18/13；颜色分为近黑、正文深灰、说明灰、单强调色，保持对比 |
| 语义色面/细框 | 对照、范围、摘要 | 服务信息分组与前后层次；不拿无功能背板填空 |

先把对齐和间距修好，再叠加原生文字样式。背景数字可与透明图片框重叠，但应在后层且低对比；不能因此忽略普通文字互相遮挡。用户要求保留正文时，样式层不改文字与事实。

## 根据真实内容量分配图文

图像主导页面可以保留，不因出现信息页而统一改成文字海报。先统计必须表达的要点、对比维度和说明深度，再分配版面；文字与图片的占比是内容的结果，不预设固定图文面积配额。

- 信息少：允许大场景、多人关系或特写作为主视觉，配少量原生文字。
- 信息较多：优先用分组标题、成对比较、步骤、信息模块等原生结构容纳真实正文；插画保留中等体量的半身、单侧场景或带动作的局部，解释主题。文字区变大时重新构图，不只是缩小上一页图片。
- 信息超出一页的舒适容量：按逻辑拆页，不靠无限缩字或删关键说明容纳。资料型可略密，但正文仍需可读。
- 纯文字大字海报是独立设计选择，只有用户明确要这种形式或内容确实适配时使用；不能把“文字较多”理解为“同样几句话放大”。

同套自然包含不同内容密度。展示高信息量样页时，选真实说明更丰富的内容段落，不强制复用原先少字封面做占比实验，也不为凑密度扩写空话。每页计划记录实际正文量、要点数、文字区、场景区、所需景别和图文接触关系；visual_priority 仅描述设计结果。

## 整套版式组织

按页面的信息关系选择构图，以下是可组合的语法，不是每套必须集齐的配额；字体与页数随主题；颜色未指定时使用默认锚点绿，不固定宋体或16页。

| 页面任务 | 图文关系与景别 | 原生信息组织 |
|---|---|---|
| 引入主题 | 阶梯标题与横向双人半身场景，共同工作物件连接人物 | 大标题、短副题，保留阅读入口 |
| 总览路径 | 文字/数字为主，可无人物 | 3–5个等宽步骤、淡色总数量、短结论 |
| 多种方向 | 中等体量半身角色解释任务 | 两行分组或矩阵，给出真实说明，不只放关键词 |
| 身份/情境比较 | 对等大小的两场景，人物关系直接表现差别 | 对齐的双列标题与解释 |
| 资产/组成 | 多人共用工作台或物件场景 | 下方原生模块与图中对象一一对应 |
| 操作证据 | 真实截图占据主要区域，手机或薄屏幕框沿边出血 | 邻近标签概括输入、操作对象与结果；保留关键上下文 |
| 前后对照 | 同景别、同缩放的两张真实截图，可用双手机 | 对齐的前后标签和判断说明，避免夸大修复效果 |
| 返修/收束 | 聚焦操作的大半身、手部细节或角色近景 | 步骤正文或可执行清单，收回全套主线 |

信息页可有较多正文，但每组说明有具体作用；需要补密度时回到原文补足原因、条件与操作，不编造事实，不靠放大少量文字填版。背景大数字、胶囊与强调色沿用语义，同套重复的是视觉语言，不是固定左右分区。

## 图形体量与景别

每页联合记录可见宽高、位置、人数、景别、轮廓和文字区关系。细长全身即使接近全高也可能弱；宽半身、双人桌面场景、巨大近景可以承担更大视觉重量。禁止以单一页高百分比决定 hero/support。

| 叙事任务 | 人物/场景选择 | 构图机制 |
|---|---|---|
| 创作/协作封面 | 双人或多人半身 + 桌面/设备 | 横向场景占据主区域，与标题交错或共用基线 |
| 身份/状态比较 | 两个对等景别的角色/场景 | 原生双列标题和解释，人物动作直接显示差别 |
| 情绪/观点 | 单人大半身/面部近景/身体局部 | 特写成为大色块，文字进入其留出的负空间 |
| 组成/资产/系统 | 多场景或人物操作物件 | 原生模块展示信息关系，人物/手势参与选择和组合 |
| 多人关系 | 2–4 人协作/冲突/对话 | 视线、手势、共同物件把人连成场景，不并排贴头像 |
| 步骤/数据 | 局部手势、小角色或无人 | 流程/图表主导，插画只指认关键内容 |

同套按内容变化景别和结构；不要求每三页凑齐全身/半身/近景，但不得连续靠同一全身站姿换左右。多人是可选叙事能力，不是每页添加陪衬的理由。

## 破框与语义接触

跨信息色面、人物遮断框线、手扶数字/框沿、局部从画布边缘进入、人物在物件前后穿插均可。角色、截图和设备允许有意超出画布，导出在页面边缘裁切。先选裁切边、完整对象位置与画内可见区域；优先裁掉角色下身、道具边缘或设备底座，保留脸、语义动作和截图关键内容。出血对象逐项声明 bleed_objects（字段见交付协议），未声明的越界仍需修复。复杂遮挡用分层素材，只有单张 PNG 时选择可单层实现的构图；正文不被遮挡。

## 真实截图与设备外框

先判断展示对象：竖屏界面或视频可配手机框，横屏软件界面可配 MacBook 框；设备外框是展示容器，不代表原截图来自该设备。真实界面、文字和数值不得由生图重造。没有真实截图时先找已提供的源素材；仍缺少时明确用占位，不伪造操作证据。

截图独立于设备框，保持比例，记录原文件、尺寸与裁切区域；默认保留讲解所需的界面上下文。放大细节时用原截图局部与原生标注，不拉伸、不把关键按钮或结论裁掉。竖屏视频装入手机时不能冒充手机 App 页面。优先使用内置 iPhone / MacBook 精细模板，按 [样机协议](device-mockups.md) 读取 manifest 并套图，不现场用粗矩形拼机身。外框与屏幕分层，仍可替换截图；复杂透视仅在叙事需要时使用。

设备周围沿用页面底色，不默认加彩色背板。MacBook 默认薄屏幕框，无键盘与厚底座；需要完整设备时另选确有用途的样机视角。框线与金属细节服务设备识别，不能压过截图。

图文可以沿设备边缘分组、围绕屏幕留出的负空间排布、用短标注指向真实区域，或让设备从底边/侧边进入。先决定截图要证明什么，再选图文关系；不固定每页左文右图，也不强制每页都加人物。外框、标注、角色不能盖住所讲解的关键信息。沿用同一间距体系与字体层级，不因加设备而另起一套装饰。

## 样页验收

对指定页面逐页渲染，比较参考：标题字形和字重是否有性格；最大文字与场景是否形成主次；空白是否可解释；动作/物件是否指向本页主题；不同页是否只是左右互换。检查信息较多页是否真的承载了更多必要内容，插画是否仍有动作、情境或语义；不能仅把少量文字放大、原图缩角就当适配完成。不能仅凭 JSON、页数、越界测试宣称风格达标。

## 几何测量调用

对象 JSON 包含 asset_base、font_files（本机字体路径和family）、spacing_system、slides；每页 objects 是 text/image（bbox、字体或素材路径），groups 可声明信息组；layout_constraints 声明 align / gap / gutter。basis=layout 检查容器节奏，basis=ink 检查真实字形/alpha 的估算列沟；不得把两者混用。gap 可引用 token；gutter 可写 min/max 光学范围，明显超限优先改布局而非扩大范围。

测量输入应使用最终手动断行；脚本不模拟目标端自动换行。图片默认居中 contain，stretch 必须显式声明；使用 cover/裁切时先提供实际显示区域的几何，不能将文件全图错误映射到裁切框。

```bash
node <本Skill>/scripts/measure_layout.mjs objects.json measured.json
python3 <本Skill>/scripts/audit_layout.py measured.json
```

align 用 ids、edge、tolerance；gap/gutter 用 a/b 两个对象ID数组和 axis。图文列沟只测正文相关组的整体可见边界，不把短行正常的行尾空白逐行当缺陷。修订间距规则或检查器时，用已知故障页与修改页回归，确保前者能被定位；普通制作检查本次实际页面，不要求构造测试夹具。脚本不替代飞书截图，不保证自动美学验收。
