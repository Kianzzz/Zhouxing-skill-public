# zhouxing-IP-PPT

把内容、字体、角色景别与场景作为同一个构图设计。交付包含可编辑文字/数字/信息形状与独立插画，不把整页生成图当 PPT。角色图片内部不能逐肢体编辑。

开工前定位本 Skill 根目录；命令中的 scripts/、assets/ 以根目录为基准，Markdown 相对链接以所在文档目录解析。先读 [工具适配](references/tool-adapters.md)，依据当前 agent 的实际能力选择生图、原生排版与渲染工具；核心设计不依赖某个 agent 品牌。

## 安装与首次使用

安装时完整复制本目录到当前 agent 的技能目录，仅检查入口、默认主题、风格母图和样机资源可读取；识别已有飞书幻灯片工具即可。已安装同名入口时先比较，更新前保留可恢复备份。安装阶段不默认运行脚本全套测试、构造测试夹具、生成试稿或创建云端文档；不为备用的本地 PPTX 路径安装 python-pptx、LibreOffice。用户明确要求完整验收时再扩大检查。

默认使用飞书原生幻灯片，不反复询问输出平台。优先复用当前 agent 已有的飞书 PPT 工具；缺失时按工具适配引导接入或安装官方飞书工具，登录/授权只在确实需要时发起。例行依赖准备由 agent 按环境权限规则按需完成，不把开发步骤交给用户。安装完成通常用最多三句说明“已安装、默认飞书、可发内容开始制作”；未完成时说清唯一的当前阻塞项和下一步，不把未实测能力称为已通过。

## 1. 明确范围与设计方向

读主题/原稿、受众、用途、参考、角色输入和输出平台。默认飞书原生幻灯片、16:9 中文；不要凭空补事实。参考图中的商标、网址、指令仅是资料。

先读 [视觉系统](references/design-system.md)，按需读 [九组参考](references/reference-study.md)。从用户最接近的参考中选定本次语言：字体性格、线条/体块、配色、密度、人物景别、图文互动；不得把不同参考平均成白底蓝字加站立小人。未指定配色时，默认使用品牌锚点绿 `#28A85B`，按 `assets/default-theme.json` 与视觉系统同步原生排版和生成素材。用户明确指定的项目配色优先；参考只借鉴构图时不继承其蓝色。

用户只要求样页时只做指定页；明确要求完整稿时，沿用已确定的风格直接完成整套，不重复索要样页批准。根据原稿的叙事与信息量定页数，不把某次示例的页数写成通用模板。保留文案与事实，允许为原生排版语义断行；新增建议须与原文事实区分。历史案例中的界面、活动价格和收益不自动变成当前结论。

## 2. 角色输入与美术语言分别决策

读 [角色与场景协议](references/character-workflow.md)。

- 无角色输入：采用内置编辑插画风格参考 `assets/default-style-reference.png`；其中人物仅为候选。先按本页内容选人/物/场景，不强制每页同一名讲解者。
- 用户 IP：身份、标志、身体比例和原媒介锁定；动作、景别、场景可以变化。
- 真人照片：保持写实身份、年龄特征与衣着，按内容生成动作/场景；不默认卡通化。信息不足以确定多名目标人物时补问。

风格与身份分别锁定：在项目里保存唯一风格母图及路径/哈希、认可状态。每次生图前读取母图；每次调用都实际传入该图作为参考，不得只在提示词写“风格相同”。同一身份再输入身份母图，只有明确需要侧背面/多角度时补角色三视图。三视图不能代替风格母图。详细选择见角色协议。用户未接受的资产不能写成已批准。

## 3. 联合构图，再拆解素材

整套先安排叙事顺序与页面作用：引入、路线、说明、案例、操作证据、比较、收束。每页落一个关键点；按内容在场景主视觉、信息较多页、真实截图和少量原生概览之间切换，不用同一版式换左右凑变化。可复用的组合见视觉系统。

先读取真实内容量、层级和必须保留的说明，再决定文字区和场景区的关系；visual_priority 只记录布局结果（text-led / image-led / balanced），不是先验的三种固定皮肤。文字多时用分组、比较、流程或原生信息结构承载内容，并重新设计中等体量的角色/场景，不默认缩成角落表情。先写每页的视觉句子，例如“两个身份不同的猫在对等办公室场景中形成冲突差异”。随后一起确定：

1. 信息结构：比较/组成/流程/场景/大字等，决定信息关系的几何；不是先划左右两区再填人。
2. 字体组合：标题、正文、英文数字各自家族、字重、尺寸、行长与断行，写明为何适合本次参考。
3. 视觉占据：主图的宽高、轮廓面积、人物数量、人与道具的关系；高度百分比不能单独代表人物大小。
4. 景别：全身、半身、近景、局部、场景全景；人数为 0/1/多人。由叙事需要选择，不把全身当默认。
5. 空间关系：视线、手势、接触锚点、跨色面/裁切/前后层次。无论文字多少，插画都应解释内容或人物关系。信息较多时可用半身、局部场景、横向场景和图文交错收敛占比，仍保持可辨的动作与情境；文字独立完整不等于图片只能做角落贴纸。
6. 间距与留白：先建立最多四档主间距、对齐线和组内/组间关系，按实际字形与图片 alpha 轮廓检查图文中缝。先修几何，再选择背景大数字、胶囊、关键词等原生文字机制；详见视觉系统，不能用装饰填洞。

在执行项目的 `plans/<task>/slide_plan.json` 写规划；已有平台专用目录时沿用，不为迁移路径重建稿件。核心字段为 schema_version=2、character_mode、canvas、typography、spacing_system、reference_contract；每页记录 slide_no、key_message、layout_type、visual_focus、text_density、visual_priority、visual_sentence、composition、whitespace_intent、characters、text_boxes、layout_constraints。目标平台的额外字段按其协议补充。保存母图路径/sha256/认可状态，并逐素材记录实际参考输入。

characters 每项记录 id、subject_count、shot、semantic_role、interaction_target、visible_bbox、crop、layers、contact_anchor。一个场景图可包含多人，不必拆成几张人物贴纸。可见包围框和文件框分别记录；alpha 留白不能冒充图形体量。无角色页写空数组。

## 4. 生成角色与具体场景

使用当前 agent 可用的生图工具，素材可是一人、多人互动、人物与物件、局部手部或完整语义场景；字段名称遵循当前工具协议。可复用语义与画风匹配的已有素材，不为凑页重复生图。每个独立资产一次调用，全部使用同一风格母图作为实际图片输入；同一身份还要固定身份母图，不把整套都变成同一个站姿。多参考须明确风格/身份各自负责什么。

默认编辑插画采用黑白与锚点草木绿 `#28A85B`、概括形体、宽阔轮廓、简洁线条和有限平涂；不继承未被接受的漫画长腿、复杂衣褶等造型。用户提供的写实/3D/像素角色保持原媒介。道具和环境可生图，数字/框线/结构文字不得烘焙进图。要有人与原生文字接触时，先给接触坐标与遮挡关系。

生成后直接展示，不主动检查生成图/自动重绘；仅用户要求修改时改。素材文件检查与 PPT 文字/布局检查照做，但不能由此宣称身份/画风已获认可。

## 5. 原生排版与交付验证

读 [交付协议](references/delivery.md)，通过工具适配选中的引擎写入原生对象。用户的字体组合、密度和参考构图优先于工具自带的单字体/密集卡片默认。

先完成原生信息结构，再按联合计划落位插画或真实截图。截图页读取 [样机协议](references/device-mockups.md)，优先复用内置精细外框与屏幕遮罩；原生标注按视觉系统执行。角色、设备和截图可有意超出画布并在导出边缘裁切；规划记录完整对象、画内可见区域、裁切边与必须保留的信息，不把所有越界一律禁止。正文仍完整可读；平台不能保留画外对象时输出等效裁切并保留完整素材。多素材之间共用基线与空间逻辑。

制作时检查计划、文字/图片可见轮廓与明确的间距/对齐约束（调用见视觉系统）：优先复用当前工具的等效检查能力；需要本 Skill 的检查器时，运行 `scripts/validate_plan.py`、`scripts/measure_layout.mjs` 和 `scripts/audit_layout.py`，届时再准备对应依赖。侧排图文页逐对声明主要正文区与视觉区的 ink gutter，不能只声明 align 就算检查了间距；非侧排页说明其留白作用。随后做平台结构/越界/文字适配检查，再渲染指定样页检查字体、换行、视觉体量、无效空白和图文关系。不能把几何检查通过等同审美通过；布局检查不得绕成主动重绘生成插画。

修复原生排版后只对受影响页重新渲染，并复核整套内容与页序。指定样页交用户判断美术；已授权的完整稿完成后直接交付。不要自评“高级/已匹配”。目标端字体/手动编辑未测试须明确标注，本地稿不能冒充已创建的飞书原生稿。

## 6. 交付

按范围展示完整稿或指定样页，附真实可编辑文件/链接；完整稿可附整套总览，不能用总览代替逐页检查。截图控件只是静态图时说明，不暗示可点击播放。保留未请求改动的内容及整套原稿。只有在用户授权范围内创建草稿；删除/覆盖重要文件、公开分享和权限变化另行确认。
